# 面试话题地图

## 1. 如果面试官让你从项目整体开始讲

优先讲：
1. 项目目标
2. provider / consumer 关系
3. 整体主链路
4. 模块划分

## 2. 如果面试官追问实现细节

继续讲：
1. 代理怎么做
2. 请求对象怎么构造
3. 服务发现和负载均衡怎么做
4. provider 怎么找到本地服务对象

## 3. 如果面试官追问设计取舍

继续讲：
1. 为什么要拆 core 和 spring
2. 为什么要拆 registry 和 discovery
3. 为什么容错做成独立层
4. 为什么要有业务线程池

## 4. 如果面试官追问扩展性

继续讲：
1. SPI 怎么支持可插拔序列化和负载均衡
2. 为什么主流程依赖抽象而不是依赖具体实现

## 5. 如果面试官追问实际价值

继续讲：
1. 项目不是只做 demo，而是打通了整条调用链
2. 已经考虑了接入方式、治理能力和可扩展性

## 6. 一句话提醒

面试时最怕的是“想到哪讲到哪”。

你最好始终围绕这条主线：

`项目目标 -> 主链路 -> 模块分层 -> 关键设计 -> 扩展和治理`
