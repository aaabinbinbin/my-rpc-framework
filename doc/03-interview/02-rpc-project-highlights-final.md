# 项目亮点怎么讲得像人话

## 1. 面试官想听什么

面试官通常不想先听你背源码，而是想知道：
1. 你做的项目解决了什么问题
2. 你实现了哪些核心能力
3. 你为什么这么设计

## 2. 当前项目可以讲的几个亮点

### 2.1 自己把完整主链路打通了

可以讲：

`这个项目不是只写了一个 demo 接口，而是把 consumer 发起调用、注册发现、网络传输、provider 执行、响应返回整条主链路真正串起来了。`

### 2.2 做了框架分层

可以讲：

`项目把入口层、调用编排层、注册发现层、协议传输层、容错治理层拆开了，后续替换或扩展能力更自然。`

### 2.3 做了 Spring / Boot 集成

可以讲：

`除了框架核心，还考虑了真实应用接入方式，通过注解和自动装配降低使用成本。`

### 2.4 做了基础治理能力

可以讲：

`除了完成基本通信，还加入了重试、熔断、降级、限流等基础治理能力，体现了对 RPC 线上问题的理解。`

## 3. 小白讲项目时最稳的顺序

推荐顺序：
1. 先讲项目目标
2. 再讲主链路
3. 再讲几个亮点能力
4. 最后讲你自己的思考

## 4. 一句话提醒

项目亮点不是“我用了很多技术”，而是“我把哪些关键问题解决了”。
