# RPC 项目亮点终版

## 3. 最值得讲的 5 个亮点

### 3.1 我做的是“骨架级重构”，不是简单堆功能

这是最应该优先讲的亮点。

这个项目的核心价值不是“我会写几个功能类”，而是“我知道一个 RPC 框架应该怎么分层，怎么把原来散掉的逻辑收清楚”。

当前项目已经拆清这些层次：

1. 配置层
2. bootstrap（启动器）层
3. 调用编排层
4. 注册与发现层
5. 协议层
6. 传输层
7. SPI 扩展层
8. 治理层
9. Spring 接入层

这很能体现设计能力，而不只是编码能力。

### 3.2 我把 consumer/provider 主链路都补完整了

这个项目不是只做了 consumer 代理调用，也不是只做了 provider server（服务端）。

而是把完整链路补到了两边。

consumer 侧包括：

1. 动态代理
2. `RpcRequest` 封装
3. 方法级配置解析
4. Filter 链
5. 服务发现目录
6. 负载均衡
7. cluster（集群容错）/ retry（重试）
8. transport 发送

provider 侧包括：

1. 请求接收
2. 协议解码
3. dispatcher（分发器）分流
4. provider Filter
5. 业务线程池
6. 本地注册表
7. 反射调用
8. 响应返回

这说明项目已经不是“单边 demo”。

### 3.3 我做了真正可替换的扩展点

这个项目不是靠大量 `if/else` 切换实现，而是收成了扩展点。

目前已经成型的扩展点包括：

1. 序列化器
2. 负载均衡器
3. Filter

这意味着：

1. 主链路不会因为实现变多继续膨胀
2. 能按配置切换实现
3. 后续继续扩展有明确入口

这很能体现“不是只会写死逻辑”。

### 3.4 我做了双侧治理能力

很多学生项目只做到“能调通”就停了，但这个项目已经把基础治理能力接进去了。

consumer 侧有：

1. 请求级重试
2. 限流
3. 服务级/方法级熔断
4. 降级

provider 侧有：

1. 方法级限流
2. 降级
3. 业务线程池隔离
4. 优雅停机

这说明项目已经开始考虑“运行时保护”，而不只是 happy path（理想主流程）。

### 3.5 我把框架接进了 Spring Boot

这体现的是工程化完成度。

当前项目已经支持：

1. `@RpcService`
2. `@RpcReference`
3. `rpc.*` 配置绑定
4. 自动装配

这意味着这个项目不只是“核心代码能跑”，而是已经具备真实 Java 项目可接入的形态。

## 4. 最值得强调的 3 个设计点

如果面试官更关注设计，不一定要讲所有功能，优先讲下面三个。

### 4.1 transport 和 invocation 分层

我明确把：

1. 服务发现
2. 方法级配置
3. 负载均衡
4. 重试
5. 熔断和降级

放在调用编排层，而不是放在 transport 层。

这样 transport 只负责：

1. 连接
2. 收发
3. 心跳
4. 重连

### 4.2 registry 和 discovery 分层

我没有把“注册中心操作”和“consumer 目录使用”混在一起，而是拆成：

1. registry（注册中心层）
2. discovery（服务发现层）
3. `ServiceDirectory`

这样 consumer 请求路径不再每次直接依赖注册中心。

### 4.3 Filter 和 runtime config 分层

我把：

1. Filter 装配
2. Filter 对应的治理运行态

拆开了。

这样：

1. `FilterManager` 只负责 Filter
2. `FilterRuntimeConfigurator` 只负责治理初始化

这类结构收口能让项目后面稳定很多。

## 5. 最能体现“你做过重构”的点

如果面试官很在意你是不是真的做过重构，优先讲这些：

1. `RpcConfigLoader` 从“大型配置解析器”拆成读取层和多个 binder（绑定器）
2. `RpcProxyFactory` 从静态全局 client 主路径改成实例工厂主路径
3. transport 选择下沉到工厂层，bootstrap 和 proxy 都能按配置切换 Netty/Socket
4. 注册中心与服务发现拆层，consumer 引入本地 `ServiceDirectory`
5. 治理能力从 transport 中抽离，统一接到 invocation/filter/runtime config（运行时配置）层
6. Spring / Spring Boot 接入从手动 bootstrap 收敛成注解和自动装配
