# 知识库维护规则

## 1. 什么时候必须更新知识库

出现以下变更时，必须同步更新 `doc/kb`：

1. 模块新增、删除、重命名。
2. 主调用链入口变化。
3. 关键类移动包路径或职责改变。
4. 配置 key、新默认值或配置绑定路径变化。
5. 注册中心、序列化器、负载均衡、过滤器、熔断限流等扩展点变化。
6. 示例启动方式、端口、注册中心依赖变化。
7. 面试表达里提到的能力已经不再符合源码。

## 2. 文件对应关系

| 变更类型 | 更新文件 |
| --- | --- |
| 模块 / 技术栈变化 | `01-project-card.md`、`02-architecture-map.md` |
| 调用链变化 | `03-rpc-call-flow.md` |
| 类路径 / 职责变化 | `04-key-classes.md`、`09-ai-context.md` |
| 配置 / 扩展点变化 | `05-config-and-extension.md` |
| Spring Boot 接入变化 | `06-spring-integration.md` |
| 启动失败 / 调试经验 | `07-troubleshooting.md` |
| 面试表达变化 | `08-interview-notes.md` |
| 知识库结构变化 | `00-index.md`、`10-maintenance-guide.md` |

## 3. 写作标准

知识库文档应该满足下面标准：

1. 以当前源码为准，不写“可能”“大概”这类没有落点的判断。
2. 每个关键结论尽量给出类名、模块名或路径。
3. 不复制教材层的大段讲解，只保留查询所需的最小上下文。
4. 对初学者不友好的深层细节要标注“第一遍不用看”。
5. 避免把 `target/`、`.idea/`、历史报告作为知识库来源。

## 4. 审查清单

每次更新后至少检查：

1. `doc/kb/00-index.md` 是否能导航到新增内容。
2. `doc/kb/04-key-classes.md` 的路径是否仍存在。
3. `doc/kb/03-rpc-call-flow.md` 是否仍能覆盖一次完整调用。
4. `doc/kb/07-troubleshooting.md` 的运行命令是否仍可用。
5. 是否引入乱码、旧包路径或已经删除的类名。
