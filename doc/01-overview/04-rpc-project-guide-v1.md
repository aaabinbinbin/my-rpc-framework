# 用最简单的话讲清这个 RPC 项目

## 1. 如果只能用几句话介绍它

你可以这样说：

`这是一个自研 RPC 框架项目。它支持把 provider 的服务注册出去，让 consumer 通过代理像本地调用一样发起远程调用；同时还提供了 Spring 和 Spring Boot 集成。`

这就是最核心的介绍。

## 2. 这个项目到底解决了什么问题

它解决的是：

`我想在一个应用里，像调用本地方法一样，调用另一个应用里的方法。`

在没有 RPC 框架时，你可能要自己处理：
1. 服务地址
2. 网络连接
3. 请求和响应格式
4. 序列化
5. 失败重试
6. 限流熔断

这个项目就是把这些事情框架化了。

## 3. 项目里有哪些关键角色

### provider

真正提供服务的一端。

### consumer

真正使用服务的一端。

### registry

帮助 provider 注册地址，也帮助 consumer 发现地址。

### proxy

让 consumer 看起来像在调用本地对象。

### transport

负责网络通信。

## 4. 为什么小白最容易看乱

因为小白一开始很容易同时看到：
1. 注解
2. Spring
3. Netty
4. 注册中心
5. 代理
6. 过滤器
7. 熔断限流

这些概念一起出现，压力会很大。

正确做法不是同时理解全部，而是先抓一条主线：

`一次调用怎么从 consumer 跑到 provider。`

## 5. 整个项目最重要的一条主线

```text
consumer 写本地调用
  -> 实际进入代理
  -> 代理构造请求
  -> 找到 provider 地址
  -> 网络发送
  -> provider 执行业务
  -> 返回结果
```

这条主线比任何包结构都重要。

## 6. 为什么项目要分那么多层

因为一条 RPC 调用其实包含很多问题：
1. 怎么接入业务代码
2. 怎么把调用变成请求
3. 怎么找到服务地址
4. 怎么通过网络发出去
5. 怎么在服务端执行
6. 失败了怎么办

把这些问题拆开，每层只处理一个问题，代码才不会乱。

## 7. 你现在最应该掌握什么

对于第一遍阅读来说，只要掌握这 4 件事就够了：
1. provider / consumer / api 三者关系
2. `@RpcReference` 和 `@RpcService` 是做什么的
3. 一次调用的主链路
4. Spring 集成只是“接入方式”，不是框架本体
