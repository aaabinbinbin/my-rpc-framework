# SPI 和扩展点小白版

## 1. 为什么框架要做扩展点

因为很多能力不应该写死。

比如：
1. 序列化可以换
2. 负载均衡可以换
3. 以后协议、压缩、鉴权也可能换

如果写死，框架很难演进。

## 2. 当前项目里最明显的扩展点

### 2.1 序列化器

比如：
1. Java
2. JSON
3. Kryo
4. Hessian
5. Protobuf

### 2.2 负载均衡器

比如：
1. Random
2. RoundRobin
3. LeastConnections
4. ConsistentHash

## 3. 什么叫 SPI

你可以先把 SPI 简单理解成：

`框架先定义接口，具体实现后面按名字加载。`

这比一开始把实现写死更灵活。

## 4. 这个项目里最重要的类

第一遍先记住：
1. `ExtensionLoader`
2. `ExtensionFactory`
3. `Serializer`
4. `LoadBalancer`

## 5. 小白怎么理解它的价值

SPI 的价值不是“高级”，而是：

1. 想换实现时，不用大改主链路代码
2. 主流程只依赖抽象，不依赖细节
3. 扩展能力更自然

## 6. 用一句话记住扩展点

`扩展点的作用，就是让框架的关键能力可插拔，而不是写死。`
