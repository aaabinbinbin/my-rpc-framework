# 传输设计小白版

## 1. 什么叫传输层

你可以把传输层简单理解成：

`请求和响应真正怎么在网络里跑。`

## 2. 当前项目里支持什么传输方式

1. Netty
2. Socket

默认更重要的是 Netty。

## 3. 为什么不能把传输和协议、代理、重试混在一起

因为它们解决的是不同问题：
1. 代理解决“怎么伪装成本地调用”
2. 协议解决“消息长什么样”
3. 传输解决“消息怎么发出去”
4. 容错解决“失败了怎么办”

## 4. Netty 在这里主要干什么

Netty 主要负责：
1. 建立连接
2. 管理读写
3. 编解码挂载
4. 请求响应收发
5. 心跳与重连

## 5. provider 端为什么还要业务线程池

因为 IO 线程适合做网络收发，不适合跑慢业务。

所以要把真正的业务执行交给独立线程池。

## 6. 第一遍先记哪些类

1. `RpcNettyClient`
2. `RpcNettyServer`
3. `RpcProtocolEncoder`
4. `RpcProtocolDecoder`
5. `RpcRequestHandler`

## 7. 用一句话记住传输层

`传输层只负责把消息可靠地发出去和收回来，不负责业务决策。`
