# 配置系统小白版

## 1. 为什么这个项目需要配置系统

因为 RPC 框架里有很多东西不能写死。

比如：
1. 用 Netty 还是 Socket
2. 序列化用什么
3. 注册中心地址是什么
4. provider 监听哪个端口
5. consumer 超时多久
6. 重试几次

如果没有配置系统，这些值全会散落在代码里。

## 2. 当前项目里的配置，大概分成两类

### 2.1 框架级配置

比如：
1. 注册中心地址
2. 端口
3. 线程数
4. 默认序列化方式

### 2.2 方法级配置

比如：
1. 某个方法超时更短
2. 某个方法不允许重试
3. 某个方法切换负载均衡策略

## 3. 为什么要区分这两类

因为有些配置对整个应用生效，有些配置只应该对单个方法生效。

## 4. 这个项目里最重要的配置类

第一遍先记住：
1. `RpcFrameworkConfig`
2. `RpcClientConfig`
3. `RpcConfigLoader`
4. `MethodConfig`
5. `InvocationOptions`

## 5. 小白怎么理解配置生效过程

可以理解成：

```text
外部配置
  -> 读取进框架
  -> 转成配置对象
  -> 调用时再按方法解析出最终生效值
```

## 6. 用一句话记住配置系统

`配置系统的作用，是把“框架该怎么跑”从代码里抽出来。`
