# 容错设计小白版

## 1. 为什么 RPC 项目一定要讲容错

因为只要有远程调用，就一定会遇到失败。

比如：
1. 网络超时
2. provider 挂了
3. 某个实例特别慢
4. 某个服务突然流量暴涨

如果没有容错，业务会很脆弱。

## 2. 当前项目里主要有哪些容错能力

1. 重试
2. 熔断
3. 降级
4. 限流

## 3. 它们分别解决什么问题

### 3.1 重试

作用：
1. 一次失败后，再尝试一次或多次

### 3.2 熔断

作用：
1. 某个服务或实例持续异常时，先别继续打它

### 3.3 降级

作用：
1. 调不通时，返回默认值或快速失败

### 3.4 限流

作用：
1. 流量太大时，主动挡掉一部分请求，保护系统

## 4. 为什么这些能力不能直接写在业务代码里

因为这些都是横切治理逻辑。

如果散在业务里：
1. 重复很多
2. 难维护
3. 框架价值就体现不出来

## 5. 第一遍先记哪些类

1. `RetryExecutor`
2. `CircuitBreakerManager`
3. `RateLimiterManager`
4. `DegradationPolicy`

## 6. 用一句话记住容错设计

`容错能力的目标不是让调用永远成功，而是让系统在失败时更可控。`
