# 协议设计小白版

## 1. 什么叫协议

在 RPC 项目里，协议可以先理解成：

`两边约定好，请求和响应到底长什么样。`

如果没有这个约定，consumer 和 provider 就没法互相理解。

## 2. 当前项目里的协议包含什么

最核心的是：
1. 消息头 `RpcHeader`
2. 消息体 `RpcRequest` / `RpcResponse`
3. 消息类型，比如请求、响应、心跳

## 3. 为什么不能直接传 Java 对象

因为网络上传的是字节，不是对象本身。

所以要经过：
1. 对象 -> 字节
2. 字节 -> 对象

这中间就需要明确协议格式。

## 4. 协议头通常解决什么问题

比如：
1. 这是不是合法消息
2. 版本是什么
3. 用的哪种序列化方式
4. 消息体有多长
5. 这是一条请求还是响应
6. requestId 是多少

## 5. 小白第一遍先记哪些类

1. `RpcHeader`
2. `RpcMessage`
3. `RpcRequest`
4. `RpcResponse`
5. `RpcMessageType`

## 6. 用一句话记住协议设计

`协议就是 consumer 和 provider 之间共同遵守的通信格式。`
