# 这套课程怎么读

## 1. 为什么这篇存在

对于零基础读者来说，最大的问题往往不是“这篇讲得难不难”，而是：

1. 我应该先读哪一篇
2. 我读的时候应该抓什么
3. 我读完以后应该达到什么程度
4. 我什么时候该停下来消化，什么时候该继续往下

这篇文档就是为了回答这些问题。

## 2. 你现在最应该避免的阅读方式

### 方式一：随机点开一篇就开始啃

比如先看 `protocol`，然后跳到 `spring`，再去看 `transport`，最后再回来看业务调用入口。

这种读法的最大问题是：

`你会不断碰到局部细节，但脑子里没有主线。`

### 方式二：一上来就试图精确掌握所有词

比如你刚看到：

1. `proxy`
2. `registry`
3. `discovery`
4. `cluster`
5. `filter`
6. `protocol`
7. `transport`

就想一次把它们定义得非常严谨。

这会让阅读体验很重。

更好的方式是：

`先接受这些词大概在做什么，再让它们在主线里逐渐稳定下来。`

### 方式三：把自己逼成“必须马上会讲”

一开始你可以讲得不完整。

只要你每往前走几篇，能比之前更顺一点地复述主线，说明你的理解就在变好。

## 3. 正确的阅读节奏是什么

### 第一轮：先建立感觉

这一轮你的目标不是精确，而是熟悉。

你应该先让下面这些事情变得“不陌生”：

1. 这个项目是一个 RPC 项目
2. 它有 consumer、provider、api
3. 它的最小闭环就是一次远程调用
4. 仓库不是一堆随机模块，而是围绕这个闭环拆开的

这一轮最重要的成果，不是你记住了什么，而是你不再害怕这个项目。

### 第二轮：先稳定一条主线

第二轮你应该做的是：

1. 盯住 `helloService.sayHello("consumer")`
2. 追它从 consumer 到 provider 的路线
3. 不断重复这条主线，直到你能稳定复述

### 第三轮：再去读源码

只有到第三轮，你才真正开始看类和代码。

因为这时候你不再是盲读，而是带着问题读：

1. 这里是在主线的哪一段
2. 这个类出现是为了补上哪一块能力
3. 它是入口，还是执行者，还是底层支撑

## 4. 每读一篇时，建议你做什么

读每一篇时，都尝试回答下面 3 个问题：

1. 这篇主要解释主链路的哪一段
2. 这篇里面我现在最该记住的 3 个词是什么
3. 我能不能不用看原文，自己把大意讲一遍

如果第三个问题答不上来，不要着急。

你可以做两件事：
1. 回头再读一遍
2. 继续往后读一篇，再回头复述

很多时候，理解不是一篇内完成的，而是在前后文来回照亮的过程中逐渐稳定下来。

## 5. 你现在最应该带着什么问题往下走

建议你带着这 4 个问题继续：

1. consumer 为什么能像本地调用一样去调用远程服务
2. provider 为什么能把请求落到真实服务对象上
3. 这个仓库为什么要拆成这些模块
4. 哪些类是我第一遍必须盯住的
